## 1. 完整系統如何分工？

```text
使用者工作台：我的工作、案件、帳跡、資料準備與治理
                         ↓
HTTP 邊界：登入、組織、細分權限、輸入檢查與重複請求控制
                         ↓
領域服務：來源 → 草稿 → 確認／覆核 → 過帳 → 對帳／更正 → 交付
                         ↓
PostgreSQL：受控寫入、版本重驗、組織隔離、期間及借貸平衡
                         ↓
背景工作：事件投影、雜湊、工作租期與失敗恢復
                         ↓
查詢與證據：案件歷程、帳務關聯、CSV、摘要包及具名審查
```

這是責任分工示意，不是每筆操作都依序經過所有元件。**工作台具名審查交接包已有專用離線檢查入口**，可在支援版本與完整材料下重算原始承諾；下載時尚未執行驗證，另行檢查也不回寫伺服器或替歷史包補材料。整份新交接檔含原指派事件的完整驗證內容，不能把畫面遮蔽範圍當成下載檔的全部揭露範圍；本地一致性仍不等於交易真實或外部採信。

| 層次 | 實際負責的問題 | 不能代替的責任 |
| --- | --- | --- |
| 工作台 | 待辦、案件搜尋／分頁、來源與欄位差異、受控操作及結果提示 | 隱藏按鈕不是授權；預填不是閱讀或覆核。 |
| 身分與 API | 個人與組織成員關係、組織切換、平台治理、命令權限與請求狀態 | 管理員名稱不等於會計核准權或專業資格。 |
| 領域服務 | 連接來源、政策、科目、版本、覆核、更正、對帳及交付 | 政策函式輸出不直接建立完整系統的入帳授權。 |
| 資料庫 | 正式內部寫入的交易邊界、借貸與期間控制、歷史保存、使用當下重驗 | 資料一致、借貸平衡不證明交易真實或分類適切。 |
| 背景工作 | 維護衍生查詢與證據、限制舊工作者及重複處理 | 排隊成功不等於投影完成；沒有資料不一定代表零餘額。 |
| 證據與維運 | 限定揭露、審查互動、部署中斷恢復、來源綁定檢查 | 本地檢查不建立外部採信、災難復原保證或上線資格。 |

主要技術為 Python／Flask、PostgreSQL、原生 JavaScript 工作台及 Docker 執行／測試環境。完整系統與公開政策模組的部署需求不同。

### AI 有三種用途，不是同一條入帳捷徑

| 路徑 | 產出與後續處理 | 不取得的權威 |
| --- | --- | --- |
| 合成會計候選 | 後端呼叫 Gemini，保存原回答、候選或拒絕結果，再按既有准入要求送人員覆核。 | 不代替認列、傳票核准、綁定或過帳；不開放正式客戶資料。 |
| Financial Insight v2 | 從所選合成案件組成事實封包，保存解讀與可核對數字引用。 | 未過帳來源不當成已過帳費用；完整期間收入、費用與損益仍不可用。 |
| 交易證據調查 v5 | 每次一案，從附件選引用，分開直接約定、異動、主張、狀態與脈絡，呈現伺服器讀回的逐字原文。 | 財務唯讀但會寫入生成證據；不自動轉成會計候選，也不保證分類與逐欄歸因正確。 |

歷史 v3／v4 按保存版本查回，不用新格式重寫原回答；v2 仍可明確選用。讀取已保存結果、引用前後文或完整回答不等於新的模型生成。

正常本機啟停工具綁定既有資料庫與 API，不藉啟動重新建庫、遷移、重設資料或呼叫模型。可選的解析前模型證據保存保留完整回答及解析失敗，與產品操作成功／失敗分開；停止時的備份可讀性檢查也不是完整還原驗收。這些是目前實作分工，不是本次重新跑過的部署成果。

新增的受限 CSV／發票文字解析目前是**離線候選產生與檢查**，不是上圖已接通的正式收件入口；保存、人工修訂／確認與入件轉接仍待實作。上述控制分工也不表示每個環節均無缺陷：10/02 真人錯配反例在 10/03 取得固定模板的有界修復與回歸；未知格式與實質閱讀仍受限制，見[反例與修後範圍](AUDIT_REVIEW_20261003.md#accounting-cases)。

完整功能分為 [12 個領域](STATUS.md#capabilities)，另列 [14 類長期暫緩](STATUS.md#deferred)。功能領域、SQL 物件及測試案例是不同單位，不相加成「總功能數」。尚未重算去除生成檔、鏡像及歷史重複後的行數，因此不刊登程式碼行數或完成百分比。

## 3. 複雜度來自哪些關聯？

| 一個表面操作 | 實際需要協調的責任 | 深入案例 |
| --- | --- | --- |
| 改科目或修正帳務 | 原來源、核准版本、新設定生效、目前認列、銀行結算及期間 | [版本與更正](CASE_STUDY.md#versioning) |
| 網頁逾時後再操作 | 使用者所見結果、原請求、交易是否提交、重試及回覆 | [未知結果與重送](CASE_STUDY.md#recovery) |
| 切換客戶組織 | 成員資格、每組織權限、session、舊畫面與仍在途的回應 | [組織與權限](CASE_STUDY.md#organization) |

這些控制不是宣稱獨創，也不表示不存在缺陷。作品展示的重點是：它們在同一個會計流程中必須協調，不能只讓單一函式或畫面看起來成功。

## 4. 公開與保留的邊界

公開完整功能摘要、狀態、上述規模口徑、選定設計案例及清理過的證據說明；保留既有[政策模組](../src/domain/accounting/posting_policy.py)與測試作為實作樣本。

完整後端、最新控制整合、資料庫 schema／migrations、完整權限與狀態轉換矩陣、恢復與發布工具、原始日誌及工作歷史仍保留私人。文件也不公開完整演算法、資料格式與規則全集。深入審閱可另按目的提供指定範圍，不直接開放完整工作庫。

公開內容可以被閱讀、下載與模仿；授權或保留部分來源不是「不會被抄」的保證。本庫以限定揭露換取可評估性，不保證已公開內容不可被複製。來源與證據分級見 [ENGINEERING_SUMMARY.json](../evidence/ENGINEERING_SUMMARY.json)。
