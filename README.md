# 帳跡 LedgerTrail｜可追溯會計與控制工作台

正式名稱為「帳跡 LedgerTrail」，工程名為 AAAS-TW／AAAS。

**把來源、會計處理、覆核、過帳、更正與交付連起來，讓人查到數字的依據、處理者、使用版本及未解問題。** 產品方向是由會計師／記帳士主導的中小企業流程；不以 AI 建議代替專業判斷。

> **這是完整私人系統的作品集，不是全部原始碼。** 公開的政策函式只是其中一個可重跑樣本；系統全貌還包括組織與平台治理、案件、科目版本、資料庫控制、背景工作、證據及故障恢復。

> **目前界線（2026-10-04 盤點）：** 10/03 已對固定模板的發票／認列證據錯配及金額精度建立有界修復與真實資料庫回歸；不代表任意文件皆可機器判真，也不證明人已閱讀。該批工程測試與收集器有成功結果，但正式 `local_engineering_readiness_passed=false`、`production_go_live_allowed=false` 仍保留，見[測什麼、怎麼測](docs/AUDIT_REVIEW_20261003.md)與[已知缺口](docs/STATUS.md#known-limitations)。

## 我的角色與 AI 分工

我以會計背景定義問題與控制目的、選擇範圍、提出驗收要求，並檢視 AI 回報與證據；實際操作遇到反例時再要求修正。具體例子是要求減少來源重抄、讓拒絕說明可定位，以及保留原錯誤案件而不是改成成功，見[需求與分工](docs/CASE_STUDY.md#contribution)。

2026-10-01～02，我親自執行公開樣本、部分私人測試命令與結果核對，並完成九項介面操作，發現上述證據錯配反例。AI 協助環境除錯、部分後續自動化、唯讀核對及證據整理；不是全部命令皆由我執行，也不是獨立第三方驗證。程式實作主要由 AI 協助，不能將工程產物說成我獨力撰寫或已完整驗證整套系統。

## 執行公開模組測試

需要 Python 3.11 以上，工作目錄為本庫根目錄：

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-test.txt
python -m pytest -q
```

Windows PowerShell 改用 `.venv\Scripts\Activate.ps1` 啟用環境。模組只用標準函式庫，測試使用 pytest 9.0.2，無須資料庫或外部服務。2026-10-04 的 **0.6.0 發布**以 Windows／Python 3.13.3、獨立環境及停用第三方外掛自動載入重跑原測試：**112 項通過，0 失敗／錯誤／略過**。程式與測試位元組仍保留原來源 `4841c001`；這個結果只驗證公開政策樣本，不是重跑 10/03 的完整系統稽核。
